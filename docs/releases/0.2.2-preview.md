## In-app updates (plan 09 S2)

- `runtime/AppUpdater.kt`: `AppUpdate` pure logic (version parse/compare, release-list parsing,
  SHA256SUMS parsing, file hashing) + `AppUpdater` state machine (Idle/Checking/UpToDate/
  Available/Ready/Failed).
- Check happens when the Settings card opens plus a manual re-check; no background polling.
  Source: `api.github.com/repos/Eboxclaw/petologic-downloads/releases?per_page=10` (not
  `/releases/latest`, which hides prereleases); newest release with an `.apk` asset whose numeric
  version beats `BuildConfig.VERSION_NAME` wins; `-preview` suffixes are ignored by the compare.
- Download reuses `ModelDownloader` (20 s idle watchdog, 4 attempts, `Range: bytes=N-` resume,
  truncate-on-200). SHA-256 is verified against the release's `SHA256SUMS.txt` before install.
- Install: verified file is exposed via a new `FileProvider` (`cache-path updates/`) and opened
  with `ACTION_VIEW application/vnd.android.package-archive`. New permission
  `REQUEST_INSTALL_PACKAGES`; the card deep-links to
  `ACTION_MANAGE_UNKNOWN_APP_SOURCES` when it is not granted yet.
- Same release signature ⇒ installing over any 0.1.6+ build never requires uninstalling.

## Website APK download fix

GitHub release assets send **no CORS headers**, so the site's streaming downloader cannot fetch
them cross-origin (proved in-browser: `TypeError: Failed to fetch`). The same APK is now mirrored
in the downloads repo at `apk/v0.2.2-preview/` and served by `raw.githubusercontent.com`
(`access-control-allow-origin: *`, Range-capable, 206 verified). The site's DOWNLOAD APK button
streams from the mirror with stall detection + Range resume (browser twin of ModelDownloader) and
falls back to the release URL's browser-managed download on any failure. iOS Safari and
streaming-incapable browsers get the plain link.
