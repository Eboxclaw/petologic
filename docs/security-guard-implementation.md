# Android Security Guard implementation

Status: working local preview, 23 September 2026. This is not a production antivirus release or completion of every roadmap phase.

Implemented on `codex/security-guard`, based on upstream `3bd344ad4c9f7b7c3027dd8a2c74cf5d7d74cfca`, in an isolated checkout. Existing unrelated working trees were preserved.

## Delivered behavior

- A Security tab and Android share destination support explicit manual file/APK and message/URL checks, findings, redacted report export, clearing history, and protection status. Sprite and widget entry points open findings.
- File scans run in a nonexported isolated Android process using passed descriptors. Streaming SHA-256, bounded archive traversal, deadlines, cancellation, and worker termination limit resource use. Traversal paths, duplicate names, nested archives and unavailable checks produce explicit limitations. A no-match result never promises safety.
- Native YARA 4.5.8 is pinned to commit `84b0e3cc0e42f8f8e6b84d19c97ec3ac6ff8aee8`. The bundled rule is a harmless scanner self-test only. There is no broad malware-family rule collection.
- A signed historical ESET subset supplies 28 exact SHA-256 indicators from VajraSpy and AridSpy. Attribution and BSD-2-Clause license ship with the assets. No malware samples were downloaded. Ed25519 validation checks payload bounds, schema, expiry, and rollback. Manual signed-pack import works.
- The signed update client is implemented behind a build-time endpoint. It downloads an expiring, monotonic manifest, applies sticky revocations, stages and hashes every required artifact before activation, rejects unsupported required content, and retains the signed manifest for audit. Interrupted activation can safely replay byte-identical signed packs, expired cached manifests cannot pass through an HTTP 304 response, and revoking a release immediately removes its reviewed vector knowledge. WorkManager schedules a daily check with network and battery constraints and exposes an expedited check path. No production endpoint is configured in the repository.
- LFM2.5-Embedding-350M now indexes typed, reviewed threat knowledge and redacted local findings into separate namespaces. Room stores versioned canonical records, edges, vectors and a durable indexing outbox; AppSearch performs exact cosine retrieval when supported, with an exact Room-backed dot-product fallback. Pack replacement, finding expiry and user deletion remove derived vectors. Security chat can retrieve reviewed records and similar redacted prior findings; similarity only selects context and cannot create or change a detector finding.
- An offline research-pack builder hashes artifacts and license manifests, enforces the production source registry, creates a canonical manifest, and signs it with an external Ed25519 key through JDK 17. Research-only feeds are excluded from release artifacts unless their production and redistribution review state changes.
- A safe efficacy harness runs the production pure Kotlin hash, URL, message and app-profile detectors against versioned inert corpora. It rejects executable/archive content, embedded payloads, active non-reserved links, credentials, PII, split leakage and missing provenance before any case runs. Reports contain only aggregate metrics and hashed case IDs. A separate opt-in offline Pixel 7a lane measures the production Liquid Embedding-350M path over at least 10,000 safe records, clears its in-memory Room and dedicated AppSearch index, and deletes the staged corpus. Full release evidence still requires the external encrypted corpus and physical run.
- Notification observation is initially off and requires Android access plus individual source-app opt-in. A bounded, coalescing queue performs local heuristics, checks revocation, and stores redacted findings. It never automatically dismisses or blocks notifications.
- After a prominent user opt-in, the validation build uses antivirus package visibility, listens for package install/update/remove events, and schedules a daily installed-app reconciliation. Before opt-in, background inventory access and event scanning stay off; user-requested single or full checks remain explicit actions. It inspects Android-visible permissions, installer origin, privileged services, target SDK, debug state and signing metadata; streams base and split APK hashes; and runs bounded static archive checks without executing app code. A version ledger skips unchanged packages. Exact local-pack matches can create high-attention findings.
- An optional k-anonymous reputation client sends only an eight-hex-character SHA-256 prefix. It verifies an expiring Ed25519-signed suffix set with the bundled trust root and performs the full-hash comparison locally. Package names, filenames, signer data, full hashes, device identifiers and model output are excluded from requests. The shard builder accepts hash metadata only and refuses sources that lack production and redistribution approval. No production reputation endpoint is configured.
- Direct and Play release paths share the same application ID. The direct release retains the verified in-app updater; `playRelease` removes package-install permission and disables updater entry points so Google Play owns updates. Signing continuity still depends on recovering and auditing the existing public certificate.
- Separate security storage retains findings for seven days, pruned on access/write. Original scanned text, senders and URLs are not persisted in findings. Explicit exports are redacted. App data wipe includes security storage and packs.
- LFM2.5-VL-450M is the one local speaking model. It can explain bounded detector evidence without tools or cloud fallback. With its separately verified optional projector, it can also discuss an image the user explicitly selects from Android Photo Picker or shares to Paladino. The image is decoded to a bounded in-memory RGB buffer, is not added to chat history or findings, and is released before text generation. Visual turns cannot call tools or create a security verdict. Image text is treated as hostile, untrusted content: raw output is buffered, tool markers fail closed, and quoted strings, URLs, IP addresses and long numbers are masked before display. The UI identifies these as fallible visual cues rather than OCR. Agent queries expose protection and canonical findings; only deterministic checks can change detector state.
- Security actions use persisted, target-bound approvals, current permission/skill checks, single dispatch claims, restart recovery, and accurate handoff/confirmation states. Changed targets and replay attempts fail closed. Notes retain their transactional, idempotent completion behavior through the shared validator.

## Architecture and limits

The input → deterministic assessment plus vector memory → generative explanation architecture has modular contracts. Deterministic heuristics and exact indicators perform fast assessment. LFM2.5-VL-450M is the default speaking model, its multimodal projector is an optional vision component, and LFM2.5-Embedding-350M is the only vector model. The 0.0.1 release adds two optional Liquid artifacts: LFM3-Omni-2B as an extra text speaker (visual turns still run on the VL-450M pair), and d1-2B as an optional decision router that can only surface a post-response Maxx offer — it never changes a route, a detector finding or an approval (see [ADR-0004](adr/0004-lfm3-stack.md)). The native runtime is llama.cpp `8642541b255bfb5dc39cd351a178be09013a55d6` (b11960 / v0.8.0), the first release carrying LFM3 architecture support. Vector-backed security similarity retrieves related reviewed context for explanations; it is outside the verdict path. The benchmark infrastructure is implemented, but the external held-out English and Portuguese corpus and Pixel 7a result are still required before ranking quality can be treated as release evidence.

Default scan budgets are 256 MiB input, 512 MiB expanded archive content, 64 MiB per entry, 4,096 entries and a 10-second scanning deadline. Native rule input is separately capped at 8 MiB, with skipped coverage reported. The isolated worker has a 12-second termination deadline and parent a 15-second wait. These bounds do not establish protection against every hostile content provider; opening a provider before descriptor transfer remains a separate limitation. ZIP central-directory consistency and APK signing are not validated by this scanner.

English and Portuguese heuristic/UI support is partial; several dynamic diagnostic labels remain English. URL checks are structural and now canonicalize internationalized domains locally, distinguish ordinary Japanese/Korean script combinations from mixed-script labels, and flag common parser ambiguities. They still have no reputation feed, public-suffix intelligence or complete Unicode confusable table. Notification snapshots are truncated and coverage is explicitly partial. Findings are not a malware-efficacy benchmark.

The bundled pack and update channel use a development public trust root. Its private key is outside the repository. Production key custody, root replacement, rotation, emergency operations and a deployed update service remain release requirements.

## Validation

- 134 JVM unit tests: core 20, security-core 9, security-scanner 20, security-benchmark 8, app 77; zero failures, errors, or skips. The smoke benchmark also passes every deterministic release threshold using the pinned inert corpus digest.
- The complete Android API 35 ARM64 emulator report contains 49 tests: 34 passed and 15 opt-in/device-dependent tests skipped, with no failures or errors. The new Pixel 7a benchmark is one of the explicit skips and refuses to run on an emulator. Coverage includes native self-test scanning, Android signature verification and idempotent replay, the Room 1→2 migration, reviewed knowledge and redacted-finding vector retrieval, pack replacement and revocation, approval revocation and replay, redacted findings, the privacy boundary copy, UI, and existing memory/security integration.
- Separate opt-in ARM64 emulator runs passed for the real VL text and vision lanes. The bounded security explanation took 1,428 ms and made no tool call. The synthetic image analysis took 2,718 ms and made no tool call; it recognized the suspicious pattern but misread or truncated some visible text, so this is runtime evidence rather than a vision-quality pass.
- ARM64 debug and unsigned release APKs built successfully. Android lint and release vital lint completed with no errors; warnings remain. R8 code optimization and resource shrinking reduced the ARM64 unsigned release APK from 85,785,259 to 20,077,633 bytes (76.6%). Explicit keep rules protect the three JNI bridges and token callback. AGP 8.13.2 supplies the R8 version required for Kotlin 2.3 metadata. Production signing and distribution packaging remain open.
- A minified checkpoint APK was locally debug-signed for emulator validation only. On the API 35 ARM64 emulator it cold-launched in 921 ms, loaded the real VL model and projector, completed a Photo Picker vision turn with hallucinated labels masked as `[unverified image text]`, loaded `libpaladino_security.so`, and matched the harmless YARA self-test. The current artifact was rebuilt after the pure-Kotlin URL hardening and passed the complete JVM/lint gates, but that exact hash was not rerun on the emulator. This validates the shrunk runtime path, not production signing or malware efficacy.
- Android CI runs the JVM and lint gates, builds both debug and minified ARM64 release variants, and retains the unsigned release APK plus its R8 mapping as a separately named artifact.
- Native library LOAD alignment was checked as 16 KiB. This is build evidence, not validation on a physical 16 KiB device.
- Speaking artifact: LFM2.5-VL-450M-Q4_0.gguf, 219,311,264 bytes; SHA-256 `6d2757dd0f0b98aea7dc90477bb5b3a0df1089be85ef92943f8cecb05121ccbf`. Its bounded synthetic explanation identified the urgent banking-details and HTTP-link pattern while explicitly declining to confirm malware. Logs and synthetic model output are under [evidence/security-guard](evidence/security-guard). Debug APK: `android/app/build/outputs/apk/debug/app-debug.apk` (generated, not committed).

Reproduce with JDK 17, Android SDK/NDK as configured in the project, and the native bootstrap steps in [Android README](../android/README.md):

```sh
cd android
./gradlew :core:test :security-core:test :security-scanner:test :security-benchmark:test :security-benchmark:benchmarkSmoke :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug -PpaladinoAbi=arm64-v8a
./gradlew :app:connectedDebugAndroidTest -PpaladinoAbi=arm64-v8a
./gradlew :app:assembleRelease -PpaladinoAbi=arm64-v8a
```

The real inference tests require the pinned models in the app's model directory and instrumentation arguments `-e realGuardModel true`, `-e realVision true`, or `-e realModel true`, depending on the lane. Without those arguments the model tests are skipped. Emulator results are not physical-device, release-signing, battery, vision-quality, or malware-detection certification.

## Remaining roadmap gates

1. Populate the encrypted external corpus with reviewed inert English/Portuguese retrieval, spam and benign cases, run its deterministic release job, and execute the safe offline Pixel 7a lane. The harness and gates are implemented; the held-out Recall@5 and 10,000-record physical latency report is still pending. Similarity remains candidate retrieval, not a malware verdict.
2. Audit the existing public signing certificate, provision production signing custody, deploy the signed update and private reputation endpoints, and exercise expiry, rollback, revocation, partial-download and recovery operations against those services.
3. Complete hostile-provider/death/cancellation tests, broaden Unicode URL confusable coverage, notification lifecycle coverage, accessibility/localization, and physical-device battery/thermal/16 KiB testing.
4. Evaluate local explanation and vision fidelity with adversarial detector evidence, visual prompt injection, OCR-heavy scams, benign screenshots, and Portuguese content. Keep tool and verdict authority outside model output. The current masking policy reduces disclosure of hallucinated exact text but does not make the model reliable OCR.
5. Measure install/download size for the intended distribution format and both supported ABIs, then evaluate ABI splits or app bundles without weakening artifact verification or compiling out the selected Liquid model path.
6. Complete the installed-app physical-device, battery and package-event matrix, obtain Play approval for antivirus package visibility, and commission an AMTSO-aligned independent lab before making established-antivirus efficacy claims. Implement call screening and VPN/network protection only as later stages with their own permissions, policies and tests.

The delivered loop is manual scan → bounded local evidence → persisted redacted finding → optional local explanation → explicitly approved OS handoff. It does not autonomously remove apps, block calls, filter network traffic, or guarantee device safety.
